01项目概述
U-Boot 是什么 · 版本概况 · 功能全景

U-Boot（Universal Boot Loader，通用引导加载器）是嵌入式领域应用最广泛的开源 Bootloader，由 DENX Software Engineering 的 Wolfgang Denk 于 2000 年发起，现由 U-Boot 社区维护， 遵循 GPL-2.0-or-later 许可证。它负责在操作系统（Linux、Android、OpenBSD 等）启动之前 完成硬件初始化，并把控制权移交给操作系统内核。

U-Boot 与 Linux 关系密切：部分源码直接源自 Linux 内核树，共享头文件，并专门为 Linux 镜像（zImage、FIT、设备树）的启动做了优化。它不仅是一个 Bootloader，还内置了一个功能完整的 Monitor（监控命令行），可用于调试硬件、读写内存、更新固件、通过网络下载程序等。

功能全景

🚀多阶段启动

BootROM → TPL/SPL → U-Boot → OS 的完整引导链，支持 MMC、NAND、SPI NOR、网络、USB、串口、Semihosting 等十余种加载介质。

🧭标准启动（Standard Boot）

bootdev / bootmeth / bootflow 三层抽象自动扫描并启动系统，开箱即用地支持 extlinux、EFI、Android、PXE 等启动方式。

🖥️UEFI 子系统

完整的 EFI Loader 实现：EFI 启动管理器、图形输出（GOP）、HTTP 启动、Capsule 固件升级、TCG2 度量启动，可直接引导 GRUB / Windows / 发行版安装器。

🧩驱动模型（DM）

类似 Linux 的 uclass / driver / udevice 设备模型，设备树驱动绑定，76 个子系统覆盖从时钟电源到显示网络的完整外设栈。

🌐网络协议栈

基于 lwIP 的网络栈，支持 DHCP(v4/v6)、TFTP、NFS、Ping、DNS、SNTP、HTTP(wget)、网络 Fastboot，并可用 pcap 抓包。

💾文件系统

ext4、FAT/exFAT、SquashFS、EROFS、UBIFS、JFFS2、BTRFS、CRAMFS、ZFS、CBFS 等 13 种，统一的 ls / load / save 命令接口。

📦下载与烧写

DFU（USB/UART）、Fastboot（USB/UDP/TCP）、UMS、Rockusb、Thor、Ymodem/Kermit 多种下载通道，配合 Capsule / FWU / RAUC 实现固件升级与回滚。

🔐安全启动

FIT 签名验证（RSA/ECDSA）、VBE 验证启动、Android AVB、TPM 1.2/2.0、度量启动、EFI Secure Boot、OP-TEE 信任执行环境。

🎛️交互界面

Hush Shell 脚本、bootmenu 启动菜单、expo/cedit 配置编辑器、开机 Logo（splash）、ANSI 彩色控制台。

🔍调试与诊断

分级日志、bootstage 计时、函数 trace、KGDB、iotrace、事件系统、cyclic 后台任务、pstore、POST 上电自检。

🧪沙箱与测试

Sandbox 架构把 U-Boot 当作 Linux 主机进程运行，配合单元测试（ut）、pytest 套件和 fuzz 模糊测试支撑 CI。

🛠️构建与镜像工具

Kconfig 配置体系、1583 个 defconfig、binman 镜像打包、mkimage/dumpimage 等主机工具、dtoc 设备树代码生成。

设计理念

  • 可配置、可裁剪：几乎所有功能都由 CONFIG_* 选项控制，通过 Kconfig 裁剪出从几 KB 的 SPL 到功能齐全的完整固件。
  • 易于扩展：所有 Monitor 命令使用统一的调用接口（U_BOOT_CMD 宏），新增命令只需一个 C 文件。
  • 动态加载：很少使用的代码（如硬件测试程序）可作为独立应用动态加载执行（go 命令 + 导出 API）。
  • 贴近 Linux：与 Linux 共享驱动模型思想、设备树格式、镜像格式，方便代码移植与生态复用。

主体内部初始化序列

U-Boot 主体的初始化分两段执行，由函数指针数组驱动的初始化序列完成，便于裁剪：

  • init_sequence_f（common/board_f.c）——重定位前：早期串口、DRAM 大小探测、板级早期初始化（board_early_init_f）、预留重定位后的内存布局（malloc 区、帧缓冲、设备树、内核预留区）。
  • init_sequence_r（common/board_r.c）——重定位后：串口全量初始化、事件、日志、环境变量加载、MMC/NAND/网络等设备枚举、中断、设备树激活，最后进入 main_loop()。

重定位（Relocation）是 U-Boot 的特色设计：代码先在加载地址运行，之后把自身整体搬移到 DRAM 高端并按偏移修正符号，从而把低地址空间完整让给操作系统内核。

main_loop 与自动启动

进入 main_loop()（common/main.c，实现在 common/autoboot.c 的 autoboot_command()）后：

  1. 倒计时 bootdelay 秒（默认 2 秒，可设 0 或 -2 禁止打断）；
  2. 倒计时内按任意键进入 Monitor 命令行（可配置加密密码：CONFIG_AUTOBOOT_KEYED）；
  3. 超时自动执行 bootcmd 环境变量中的命令串；
  4. preboot 变量在 bootcmd 之前执行，可用于显示开机 Logo；
  5. 失败回滚：bootcount 计数持久保存，超过 bootlimit 次后改执行 altbootcmd 备用启动命令（A/B 升级场景的保命机制）。

04标准启动 Bootflow
bootdev · bootmeth · bootflow 三层自动启动框架

标准启动（Standard Boot，bootstd）是 v2022.10 引入、如今默认的启动框架，目标是取代以往每块板各写一套 bootcmd 脚本的做法：U-Boot 自动按启动顺序扫描各个启动设备， 尝试每种启动方法，找到第一个可用的启动流并执行，全程无需手写脚本。

三个核心概念

概念uclass含义
bootdev 启动设备UCLASS_BOOTDEV"从哪里启动"：MMC、网络、USB、SCSI、VBE、EFI 介质等，每个存储设备可派生一个 bootdev
bootmeth 启动方法UCLASS_BOOTMETH"怎么启动"：解析 extlinux.conf、扫描 EFI ESP、执行 boot.scr、PXE 网络启动、Android boot.img 等
bootflow 启动流软件对象"一次启动尝试"：某 bootdev + 某 bootmeth 找到的完整启动方案（含内核、设备树、initrd 的加载地址）

启动顺序与 hunter 机制

扫描顺序由环境变量 boot_targets 决定（默认形如 mmc0 mmc1 mmc2 usb0 pxe dhcp），也可用 boot_order() 按 uclass 优先级自动推导。hunter（猎人）机制会在扫描时按需枚举总线上新出现的设备 （例如扫描到 usb bootdev 前先做 USB 总线枚举），无需提前初始化所有外设，加快冷启动速度。

06UEFI 支持
lib/efi_loader · EFI 启动管理器 · Capsule 升级 · 度量启动

U-Boot 实现了完整的 UEFI（统一可扩展固件接口）子系统（lib/efi_loader/， 100+ 源文件），具有双重身份：

  • EFI 宿主（host）：加载并运行 EFI 应用——GRUB、systemd-boot、Windows 安装器、Linux 发行版安装介质、EFI Shell 程序等；
  • EFI 载荷（payload）：自身可作为 coreboot / EDK2 / SlimBootloader 之后的 EFI payload 运行（CONFIG_EFI_APP，lib/efi_client）。

09驱动模型 DM
Driver Model · uclass / driver / udevice · 设备树绑定

驱动模型（Driver Model, DM）（drivers/core/）是 v2014.10 引入、 现在强制的设备抽象框架，思想与 Linux 内核的设备模型一致：把"设备类别"抽象为 uclass， 把"具体实现"抽象为 driver，运行实例为 udevice，三者通过设备树（device tree）连接。

核心概念

概念说明
uclass一类设备的公共接口（如 UCLASS_MMC、UCLASS_I2C、UCLASS_ETH），定义统一 API 与该类设备链表
driver某芯片的驱动实现（如 rockchip-dw-mmc），声明 compatible 匹配表、probe/remove 回调、私有数据大小
udevice运行期设备实例，由设备树节点（ofnode）或平台数据生成，挂到所属 uclass
uclass driver管理整类设备的公共逻辑（枚举顺序、ops 分发）

生命周期：bind → probe

  1. bind（绑定）：解析设备树，按 compatible 匹配驱动并创建 udevice，建立父子拓扑（如 I2C 总线下的子设备）；此阶段不碰硬件，开销极低。
  2. probe（探测）：首次使用时才初始化硬件——时钟、引脚、电源、寄存器；失败可返回错误延迟重试。
  3. remove：卸载（多用于测试与 USB 热插拔）。

常用 API：uclass_get_device(UCLASS_MMC, 0, &dev) 按序号取设备并自动 probe、 dev_read_* 读设备树属性、device_get_uclass_priv() 取类私有数据、 ops 结构体调用该类统一操作接口。

SPL 场景：of-platdata

SPL 中没有完整的 libfdd/设备树解析空间时，可用 of-platdata（dtoc 工具）： 构建时把设备树编译成 C 平台数据结构直接链入镜像，驱动同时支持两种数据来源（of_to_plat 回调统一适配）。

配置体系

  • Kconfig：数千个 CONFIG_* 选项组成依赖图，菜单化裁剪（最小编译可到几十 KB）；
