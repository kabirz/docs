Modbus 协议详解

Modbus 是一种诞生于 1979 年（Modicon / 施耐德电气）的工业现场总线通用协议 — 基于 OSI 模型第 7 层（应用层），采用主从式（Client/Server）请求-应答通信机制，是最普及、最简单、最开放的工业通信协议之一。
应用层协议 主从广播模型 RTU / ASCII / TCP 端口 502 RS-485 / 以太网 开源免版税

1协议概述

Modbus（莫迪康总线）是工业自动化领域使用最广的通信协议之一，几乎所有 PLC、HMI、变频器（VFD）、传感器和智能仪表均支持该协议。

属性说明
发明者 / 年份Modicon（1979 年，现属施耐德电气 Schneider Electric）
协议位置OSI 模型第 7 层（应用层），基于请求-应答（Request/Response）
通信模式主从式（Master/Slave），即客户端/服务器（Client/Server）模型
当前维护组织Modbus Organization（Modbus.org），规范 V1.1b3（2012）
主要变体Modbus RTU、Modbus ASCII、Modbus TCP/UDP、（Modbus Plus 专有）
特点开放、免版税、实现简单、报文紧凑、适用于多种物理介质
可靠性串行链路由 CRC/LRC 校验 + 帧空闲间隔保证；TCP 由 TCP/IP 保证
安全性原生无加密/认证；可通过 Modbus/TCP Security（TLS，端口 802）增强
Modbus 之所以经久不衰：数据结构简单、占用资源少、实现成本低、兼容性极好，特别适合需要稳定可靠读写寄存器与开关量的工业场景。

2通信模型与原理

Modbus 采用单主站（主）/多从站（从）的广播-应答机制，一切通信由主站发起。

概念角色规则说明
客户端（Master 主站）发起通信的一方主动发送请求，分配从站地址，控制广播；通常是 PLC、上位机、网关。
服务器（Slave 从站）响应请求的一方监听总线，仅当请求中地址与自身相符或为广播时才做出响应。
查询 - 响应周期基础交互主站向特定从站发送查询 → 从站返回响应（正常或异常）。
广播主站向从站 0目标地址 0（0x00）表示广播；所有从站执行但不返回响应，仅用于写操作。
地址范围有效从站地址串行链路 1~247；0 为广播地址；248~255 保留。
帧间隔RTU 分帧相邻两帧之间至少保持 3.5 个字符的空闲时间（T3.5）。
关键约束：同一总线上所有设备的传输模式必须一致（不能混用 RTU 与 ASCII）；主站任一时刻只能有一个事务在网络上，因此天然无冲突。

4数据模型（四种数据表）

Modbus 将设备数据抽象为四张独立的表，每张表最大 65536 个可寻址项。表中数据的"含义"由设备厂商定义，协议只规定地址空间。

1 起始 vs 0 起始陷阱：文档上用传统 5 位地址（如保持寄存器 40001），而报文内使用 0 起始地址。请求时需减 1（40001 → 0x0000）。不同厂商约定不同，务必核对设备手册。

5寻址模型

Modbus 的寻址包含从站（单元）寻址与数据对象寻址两个层面。

寻址项位数说明
从站地址（Unit/Slave ID）1 字节（0~255）RTU/ASCII 中为从站地址；TCP 的 MBAP 中用单元标识（Unit Identifier）表示。
有效从站地址1~2470 用于广播，248~255 保留。
数据对象地址16 位（0~65535）每张数据表内从 0x0000 到 0xFFFF。
数据对象数量16 位请求中指定读取/写入的对象数量（受最大值限制）。
在 Modbus TCP 网关后接多个 RTU 从站的场景中，TCP MBAP 的单元标识（Unit Identifier）常被置为下游从站地址（1~247），用于网关路由。

6功能码分类

功能码是 Modbus 请求/响应 PDU 的核心，决定执行何种数据操作。功能码分为三类：

类别代码范围说明
公共功能码（Public）已定义标准功能码由 Modbus.org 定义，功能唯一、实现受到约束，通用性最强。
用户定义功能码（User-Defined）65~72、100~110 + 其余保留区由用户/厂商自由定义使用，不保证跨厂商通用。
保留功能码（Reserved）其余未定义留作将来扩展，当前不得使用。

功能码操作组划分

7B线圈（Coil）详细报文协议

线圈（Coils）是 Modbus 四种数据表中唯一的单比特读/写对象，用于开关量输出（继电器、指示灯、阀门开合等）。本节给出 FC01 读、FC05 写单、FC0F 写多三种操作的完整报文结构与位打包规则。

三种线圈操作的功能码汇总：读 = 01 (0x01)、写单个 = 05 (0x05)、写多个 = 0F (0x0F)。其中 05/0F 支持广播（地址 0），01 不支持。

① FC01 (0x01) 读线圈 Read Coils

读取 1~2000 个连续线圈的状态（ON=1 / OFF=0）。一次最多读 2000 位（250 字节）。

方向字段长度说明
请求从站地址 / 单元ID1 字节1~247（TCP 中为 Unit ID）
功能码1 字节0x01
起始地址2 字节第一个线圈的 0 起始地址（0x0000~0xFFFF）
线圈数量2 字节1~2000（0x0001~0x07D0）
校验（RTU）2 字节CRC-16；TCP 无此字段
响应从站地址 / 单元ID1 字节回显
功能码1 字节0x01
字节数1 字节返回数据字节数 = ⌈数量/8⌉
线圈状态N 字节按位打包的状态值（规则见下）

位打包规则（关键）：返回的每个字节按位表示线圈状态。字节内最低位（bit0）对应起始线圈，依次递增；一个字节最多容纳 8 个线圈，超出部分放入下一字节。

字节Bit 7Bit 6Bit 5Bit 4Bit 3Bit 2Bit 1Bit 0（LSB）

易错点：Modbus 采用 LSB-first（低位在前）打包，与多字节大端数据不同。解析时必须从每字节的 bit0 开始映射到起始线圈，切勿按 bit7 对齐。

将单个线圈置 ON（0xFF00）或 OFF（0x0000）。响应 = 请求的回显。

完整报文实例

示例 A：FC05 写单个线圈置 ON（RTU，从站 01，线圈地址 0x0001）

方向RTU 十六进制解析
请求01 05 00 01 FF 00 DD FA地址01，FC05，线圈0001，FF00=ON，CRC
响应01 05 00 01 FF 00 DD FA回显，写入成功

示例 B：FC01 读 10 个线圈（RTU，从站 01，起始地址 0x0000）

方向RTU 十六进制解析
请求01 01 00 00 00 0A 3D 0D读起始00起10个线圈 → 需 2 字节
响应01 01 02 CD 6B 0B 08字节数02；CD=线圈1~8，6B=线圈9~10
响应位解析：字节 CD = 1100 1101，LSB 起 → 线圈1=1、2=0、3=1、4=1、5=0、6=0、7=1、8=1；字节 6B = 0110 1011 → 线圈9=1、10=1。说明：CD 与 6B 的位序均为 bit0 对应本组第一个线圈（本例仅演示打包位序，具体地址映射以设备手册为准）。

示例 C：FC0F 写 10 个线圈（RTU，从站 01，起始地址 0x0000）

方向RTU 十六进制解析
请求01 0F 00 00 00 0A 02 CD 01 BF 0B写10线圈，数据2字节：CD 01
响应01 0F 00 00 00 0A 6F F0回显起始地址0000 与数量000A
广播注意：FC05 / FC0F 用地址 0 广播时，所有从站执行写入但不返回响应。FC01 读操作不支持广播。

8报文帧格式（RTU / ASCII / TCP）

Modbus 报文由 地址域 + 功能码 + 数据域 + 校验域 组成。三种变体的 ADU（应用数据单元）外层不同，但内部 PDU（协议数据单元）结构一致。

变体报文结构（ADU）
PDU（通用）功能码(1B) + 数据域(NB)
RTU ADU从站地址(1B) + PDU + CRC-16(2B)
ASCII ADU":"(起始) + 地址(2字符) + PDU + LRC(2字符) + CR LF
TCP ADU事务标识(2B) + 协议标识(2B) + 长度(2B) + 单元标识(1B) + PDU

① Modbus RTU 帧格式

字段长度说明
从站地址 Slave Address1 字节1~247，0 为广播地址
功能码 Function1 字节指定读写动作，如 0x03 读保持寄存器
数据域 Data0~252 字节含寄存器地址、数量、数据值等
CRC-162 字节低字节在前，高字节在后
RTU 帧 | 地址 | 功能码 | 数据域 | CRC低 | CRC高 |
ADU 总长 = 4 + 数据长度（最大 256 字节）
帧两侧必须 ≥ 3.5 个字符时间的空闲间隔（T3.5）

② Modbus ASCII 帧格式

字段编码说明
起始符1 字符冒号 ":"（ASCII 58）
从站地址2 字符十六进制 ASCII（0~9、A~F）
功能码 + 数据N 字符每个字节以两个十六进制字符表示
LRC 校验2 字符8 位纵冗余校验
结束符2 字符回车 CR + 换行 LF

③ Modbus TCP 帧格式（MBAP）

字段长度说明
事务标识 Transaction ID2 字节客户端用于匹配请求/响应
协议标识 Protocol ID2 字节Modbus 恒为 0x0000
长度 Length2 字节后续 Unit ID + PDU 的字节数
单元标识 Unit ID1 字节类似从站地址，0~255；纯 TCP 常设为 0 或 0xFF
PDU0~253 字节功能码 + 数据
Modbus TCP 不重新加 CRC：TCP/IP 已保证数据完整性、有序性与可达性，因此省去 CRC，并移除串行帧的沉默间隔分帧逻辑。

10异常响应码

当从站无法处理请求时，会在响应中把功能码最高位置 1（原功能码 + 0x80），后面跟 1 字节异常码。

异常响应格式
RTU：地址 | 功能码 + 0x80 | 异常码 | CRC16
TCP：MBAP头 | 功能码 + 0x80 | 异常码
异常码 (Hex)名称含义
01 (0x01)Illegal Function
非法功能		从站不支持该功能码
02 (0x02)Illegal Data Address
非法数据地址		地址超出设备支持的寄存器/线圈范围
03 (0x03)Illegal Data Value
非法数据值		数据域中的值超出允许范围
04 (0x04)Slave Device Failure
从站设备故障		从站处理时发生不可恢复错误
05 (0x05)Acknowledge
确认		已接受请求且正在处理，需要较长时间（长时命令）
06 (0x06)Slave Device Busy
从站设备忙		从站正忙，要求稍后重试
08 (0x08)Memory Parity Error
内存奇偶校验错误		扩展内存奇偶校验失败
0A (0x0A)Gateway Path Unavailable
网关路径不可用		网关无法为请求路由
0B (0x0B)Gateway Target Device Failed to Respond
网关目标无响应		下游设备未在超时内响应
若主站收到异常响应，应解析异常码定位问题（例如 0x02 常由"1起始/0起始地址偏差"引起，0x03 常因功能码数量字段错误）。

11数据校验（CRC-16 / LRC）

串行链路（RTU/ASCII）需要额外的差错校验；TCP 依赖传输层保护，无需帧校验。

CRC-16（RTU 使用，多项式 0xA001）

步骤说明
1. 初始化CRC 寄存器置 0xFFFF
2. 逐字节异或将当前字节与 CRC 寄存器低字节异或
3. 右移 8 次对每一位右移，若最低位移出为 1，则与 0xA001 异或
4. 全部字节处理完得到的 CRC 值，低字节在前、高字节在后追加到帧尾
CRC-16 参考实现（C 语言）
uint16_t crc16(uint8_t *data, uint16_t len){
  uint16_t crc = 0xFFFF;
  for(uint16_t i=0;i<len;i++){
    crc ^= data[i];
    for(uint8_t j=0;j<8;j++){
      if(crc & 1) crc = (crc>>1) ^ 0xA001;
      else crc >>= 1;
    }
  }
  return crc;
}

LRC 校验（ASCII 使用）

步骤说明
1. 累加将地址、功能码、数据各字节累加
2. 求补码对累加结果取 2 的补码（逐位取反 + 1）
3. 编码结果以两位十六进制 ASCII 字符表示

12通信时序与定时参数

Modbus RTU 的帧分隔与超时以"字符时间"为单位计算。字符时间 = 11 bit / 波特率。

参数倍数用途
T1.51.5 个字符时间帧内字符间的最大间隔（字符间超时）
T3.53.5 个字符时间帧间最小静默间隔，用于分帧；发送前主站必须静默 ≥ T3.5
响应超时串行 500ms~3s，TCP 1s~5s主站等待从站响应的最大时间

不同波特率下的定时值

波特率 (bps)字符时间 (ms)T1.5 (ms)T3.5 (ms)

自定义固件实现时常把 T3.5 算错，导致帧粘连、CRC 偶发失败。建议由库根据波特率自动计算静默间隔。

13字节序与多字节数据解析

Modbus 寄存器为 16 位字。32 位数据（long、float、时间戳）需占用两个连续寄存器。规范不强制字节序，由厂商决定，解析时必须核对设备手册。

约定排列方式（值 = 0x12345678）常见厂商
大端 ABCD高字在低地址，字内字节大端：12 34 56 78施耐德部分设备、部分 ABB
小端 DCBA低字在低地址，字内字节小端：78 56 34 12Allen-Bradley、多数 Wago
字交换 BADC低字低地址，字内字节交换：56 78 12 34部分 Honeywell、BACnet 网关
字节交换 CDAB高字低地址，字内字节交换：34 12 78 56个别 Beckhoff 端子
验证技巧：写入一个已知值（如 0x12345678），再读回原始字节流比对，即可确认设备的字节序。（可用 Modbus Poll、QModMaster、Diagslave 等工具查看原始字节。）

14RS-485 物理层与布线

Modbus RTU 最常见的物理层是 2 线半双工多点 RS-485 总线。布线失误是现场调试耗时最多的原因。

项目规范 / 建议
节点数量经典每段 32 个单位负载（UL）；现代 1/8 UL 收发器最高支持约 256 节点
总线长度9600 bps 下最长约 1200 m；115200 bps 下缩至约 200 m
终端电阻仅在总线两端各装 120Ω 匹配电阻；中段设备移除跳线
偏置电阻通常在主站加 680Ω 上拉/下拉（D1 上拉、D0 下拉到 5V），防止空闲线噪声
线缆屏蔽双绞线（如 Belden 3106A），屏蔽层单端接地
共模电压相对主站信号地保持 -7V ~ +12V 内
空闲差分电压D+ 与 D- 间 ≥ 200mV（建议 200mV~5V）
支线长度支线（stub）尽量短，建议 < 20 m
偏置与终端电阻不可在同一设备上同时安装，否则会形成分压器把总线 DC 电平拉偏。

15诊断功能（FC08 子功能）

功能码 0x08 用于主从之间的诊断测试，从站回显子功能码和数据域。

子功能码名称用途
00 00Return Query Data回显测试（回路环回）
00 01Restart Comm Option重启通信，可重置从站计数
00 02Return Diagnostic Register返回 16 位诊断标志
00 04Force Listen Only Mode强制只听模式，从站停止响应（网络诊断用）
00 0AClear Counters清零所有计数器和诊断寄存器
00 0BReturn Bus Message Count自上次清零以来收到的消息总数
00 0CReturn Bus Comm Error CountCRC/奇偶/帧错误计数（衡量链路质量）
00 0DReturn Slave Exception Error Count返回的异常响应次数
00 0EReturn Slave Message Count发给本从站的消息数
00 0FReturn Slave No Response Count寻址到但从站未响应的次数
用途：用子功能 0x0C 统计 60 秒内的通信错误增长速率，可定位终端、偏置或线缆问题。

16网关与安全

串口转以太网网关

典型现场架构为 Modbus TCP 主站 → 串口转以太网网关 → RTU 多从站总线。网关改写 MBAP 头，把目标从站地址填入单元标识（Unit ID），并转发带 CRC 的 PDU。

场景Unit ID 设置结果
指向单一下游从站目标从站地址（1~247）正确路由并返回单个响应
设为 0xFF广播至全部从站导致串行链路冲突，避免

安全考虑（Securing Modbus）

原生 Modbus 无认证、无加密（仅串口 CRC 完整性校验）。在工厂网络中部署建议：

措施说明
独立 VLAN将 Modbus 段隔离，不与办公网互通
入口 ACL在 TCP/502 上仅放行授权的 Modbus 主站 IP
VPN/MACsec跨不可信链路时加密隧道
关闭多余功能码网关若不使用 FC43 封装传输则禁用
Modbus/TCP Security按 IEC 62443 启用 TLS（端口 802）增强安全性
